# Français et anglais

Dublao utilise LocaleMiddleware et les catalogues Django standard. Le français
est la langue de secours. Le navigateur peut proposer l'anglais ; le choix
explicite dans le sélecteur FR / EN de la navigation prend la
priorité et est mémorisé dans un cookie pendant un an.

Le sélecteur figure dans les en-têtes et dans la barre de la fenêtre de
connexion/inscription pour rester accessible lorsqu'elle est ouverte. Le choix
est envoyé automatiquement, sans bouton Appliquer, puis recharge la page
courante. Enregistrer les formulaires et terminer les imports avant de changer
de langue : un formulaire non envoyé n'est pas conservé après rechargement.

Les textes de l'accueil, du compte, du studio, du portefeuille et de
l'administration, ainsi que les emails transactionnels personnalisés, sont
marqués avec `translate`, `blocktranslate` ou `gettext_lazy`. Les emails prennent
la langue active de la demande. Les commandes et tâches sans demande utilisateur
emploient la langue par défaut. Les messages de travail enregistrés sont traduits
au moment de leur affichage, sans modification des enregistrements.

Les dates gardent le format jour/mois/année déjà choisi pour ces interfaces ;
les nombres sont formatés selon la langue active. Les codes de langues Murf,
les statuts internes, les montants et les règles de paiement restent inchangés.
Les titres de projets, biographies et autres contenus saisis par les utilisateurs
ne sont pas traduits automatiquement. Les interfaces tierces Google, Murf et
Genius Pay ne sont pas pilotées par ces catalogues.

## Catalogues et Docker

Les sources éditables sont `locale/en/LC_MESSAGES/django.po` (Python/templates)
et `djangojs.po` (JavaScript). Les fichiers `.mo` compilés sont aussi présents
pour le lancement local sans installation de gettext sous Windows. Docker
installe gettext et recompile les deux catalogues pendant la construction.

Après une modification, reconstruire les services :

```powershell
docker compose up -d --build
```

Pour compiler hors Docker, installer GNU gettext puis exécuter
`python manage.py compilemessages`. Pour extraire de nouveaux textes, utiliser
`python manage.py makemessages -l en` et `python manage.py makemessages -l en -d djangojs`.
Les appels JavaScript à `translateStudioText`, `translateLandingText` et
`translateAuthText` doivent être ajoutés comme mots-clés d'extraction si
l'extraction JavaScript est automatisée ; garder les messages dynamiques et
leurs variables distincts.

## Vérification

Les tests `dublao.test_i18n` couvrent le cookie, le changement de langue, les
redirections sûres, les pages publiques et protégées, les emails, les statuts
et le catalogue JavaScript. Les tests existants restent exécutés en français.
